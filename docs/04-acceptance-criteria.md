# Acceptance criteria — objective release gates

Status convention: `[ ]` not verified, `[x]` tested with command and evidence in CI; do NOT mark complete merely because source exists.

## Build and model

- [ ] AC-01: `docker compose config` validates; model files absent from ZIP/repo.
- [ ] AC-02: download selects exactly `AD-IQ4_NL` decoder (19.68 GB decimal) + `Encoder-F16` (1.67 GB decimal); validated files exist and are read-only for runtime.
- [ ] AC-03: CPU backend built against pinned upstream SHA; `/ready` becomes ready and `/v1/models` contains SALM capability.
- [ ] AC-04: Romanian 30-second clean WAV from independent ground truth produces a non-empty, readable transcript, retaining diacritics.

## Upload and workflow

- [ ] AC-05: UI accepts MP4, MKV, WAV, MP3 and FLAC, with single and multiple uploads. Corrupt/empty/unsupported files yield explicit errors and never invoke the model.
- [ ] AC-06: files are streamed; 1 GB upload does not cause ~1 GB growth in web RSS.
- [ ] AC-07: 60-minute MP4 audio stream is split and processed in sequential chunks; no 60-minute single-request VRAM context is accidentally allocated; progress 0 → 100.
- [ ] AC-08: Only one active transcription request to upstream per worker/host; 5 queued uploads do not crash or duplicate jobs.
- [ ] AC-09: Web restart does not lose uploads; worker crash recovers in-flight job, with idempotent result writing.
- [ ] AC-10: TXT/JSON outputs are downloadable and consistent; SRT is downloadable only when actual aligned words are provided. Subtitles never fabricate fine-grained timestamps.
- [ ] AC-11: Romanian file `Știință în București.mp4` and transcript `Țară, școală, înghețată` are handled in UTF-8 end-to-end.
- [ ] AC-12: Global word offsets respect the original media timeline (absolute error <= 500 ms on a synthetic timestamped test with known splits).
- [ ] AC-13: HTTP 400/413/422 yields failed job, 429/5xx gets bounded retry and eventual failed state; no infinite loop.

## Hybrid performance and GPU proof

- [ ] AC-14: Actual patched NVIDIA/NeMo-Speech.cpp fork + exact commit/patch checksum are provided, tested and legally reviewed. `n_cpu_moe` or equivalent explicitly accepted by binary.
- [ ] AC-15: On **RTX 3080 10 GB**, 60-second Romanian WAV succeeds with GPU actively computing; `nvidia-smi` recorded GPU load and VRAM staying <= 9.0 GiB at peak; system RSS stays within available 64 GB.
- [ ] AC-16: Same input transcribed via CPU and hybrid modes; no systematic degradation beyond predefined WER tolerance (suggest <= 1 absolute WER point, pending curated reference).
- [ ] AC-17: RTFx measured for at least 5 short clips and 1 full-hour recording, including p50/p95 segment latency, disk throughput, GPU load, peak RAM/VRAM; results documented, not assumed.
- [ ] AC-18: 3 sequential videos process without GPU OOM, model reload or leaked memory; CPU fallback is selectable and works when patch absent.

## Security / operations

- [ ] AC-19: UI published only on 127.0.0.1; NeMo API has no host port; Docker volume paths constrained and upload filenames not used for shell invocation.
- [ ] AC-20: Non-root web/worker, configurable upload cap; clean-up / disk exhaustion behavior documented.
- [ ] AC-21: Dependencies and upstream source pinned for reproducible builds, license notices preserved.
